# EveryoneBench 立项调研(anti-scoop 复查)

> 灵感:**AI 终态里,一个 agent 同时服务无数用户(user1 … user∞),用户之间的指令会冲突。当前模型训练时把一切都当"user"处理,不分主体——多用户冲突下的行为从未被系统评测。**
> 本文件是发布前的诚实复查:**这个方向在 2026 年已有大量工作**,下面是完整清单与本项目的精确差异化。

## 1. 已有工作(2026 深度复查,按轴分组)

### 多用户框架与综合能力
| 工作 | 出处 | 覆盖 | 我们的差异 |
|---|---|---|---|
| **Multi-User LLM Agents** | arXiv 2604.08567 | 形式化框架 + 多用户交互四能力(角色/权限/偏好) | 组织场景为主;未把"用户规模"作为变量、未测与多任务混合的交叉 |
| **Harness-MU** | arXiv 2606.21856 | 多用户 agent harness(权限、权威冲突、防泄露) | 是 harness(系统定义),不是可扩展评测协议 |
| **GroupTravelBench** | arXiv 2605.25200 | 多用户、多轮旅行规划中的冲突识别与解决 | 单域(旅行)、少量用户 |

### 忠诚 / 代理边界
| **PrincipalBench / Whose Side Is Your Agent On?** | arXiv 2606.30383 | 多主体忠诚(代表 principal 与 counterparty 对抗) | 双边结构(1 principal + 1 counterparty);我们做 N 边与关系图 |
| **Manager Coercion Benchmark** | arXiv 2607.15434 | AI-to-AI 管理中的强制/欺骗 | agent-agent 层级,非用户群体 |

### 冲突类型学(分散覆盖)
| **IH-Benchmark** | arXiv 2607.25987 | 指令层级(system > user > tool)的冲突鲁棒性 | 信任层级,非用户间冲突 |

| **KC-Bench** | arXiv 2609.03588 | 用户指令 vs 参数知识 vs 环境观测的知识冲突 | 知识轴 |
| **SoCRATES** | arXiv 2606.05563 | 社会冲突调解(600 场景,8 域) | 第三方调解者视角的主观评估;非 agent 作为服务方的仲裁正确性 |

## 2. 结论:方向已被覆盖,但三个空白仍在

**已被覆盖**:多用户权限/偏好框架、单域冲突解决、忠诚、隐私、层级冲突、角色冲突、单用户升级决策。

**未被覆盖(本项目定位)**:

1. **规模与结构轴**:现存工作全部是 2–5 个用户。终态是"user1 … user∞"。EveryoneBench 把**用户数(2→64+)与关系结构(层级/联盟/对立/授权链)**做成实验变量。
2. **多用户 × 多任务交叉**:无人测"同一个 agent 既扛无数用户、又扛无数任务"——这是 MyriadBench 与多用户研究的自然交汇,也是终态形态本身。
3. **冲突类型学作为可插拔注册表 + 升级路径一等指标**:现存工作各自覆盖 1–2 类冲突;没有一份把 8 类冲突(资源/约束/优先级/权限/隐私/代理范围/身份混淆/不可调和)做成开放注册表,并把"该不该升级、升级给谁、升级前如何安全暂缓"作为独立指标(尤其与隐私、越权联合)。
